# A release page for each download

- **Decided:** Each time the downloads on R2 are cut, a GitHub release page goes up for the version the ISO installs: named "CabinetOS" and that version, tagged at the commit its image was built from (the image's `org.opencontainers.image.revision` label), and marked Latest. It carries the last page's text, a short list of what is new since that page with a link to the wiki's What's new, and links to the downloads and their SHA-256 files on R2, never a checksum or a size typed in. Earlier pages stay as the history; the 2026.10.10 page, made before this, gets the same links in place of its typed checksum and size. A session drafts each page and MMagTech gives the go before it is published.
- **Date:** 2026-11-13
- **Why:** A cut replaces the same file names on R2, so a page beside them goes stale unless it moves with them. Only 2026.10.10 ever had a page: by 2026-11-13 the ISO on R2 installed 2026.11.13.2 while that page still printed the first ISO's SHA-256 and size, so anyone checking the download against it saw a mismatch, and its source line pointed at a tag a month older than the file. A new page for each cut, rather than editing the one page, keeps each tag and source line true and leaves a history. The checksum is a link because the file under the link changes and a typed number would not. A page for each cut and not for each update, because updates reach consoles through System update, often several a day, and a page matters only to someone downloading.
- **Numbers:** #705, "Downloads: the base update says when to cut them, and the ISO goes up from the run that was checked"; #308, "At the first release: the download goes on a GitHub Release, and the page and wiki point to it".
- **Replaces:** "The GitHub release for each update stays by hand" in docs/SETTINGS.md (What's new), which was never kept up.
