# The controller Eden, Cemu and Vita3K are given is a stand-in DualSense Edge, with Sony's id

- **Decided:** The virtual controller the console gives Eden, Cemu and Vita3K is a `/dev/uhid` device with Sony's DualSense Edge id, 054C:0DF2, over USB, named "CabinetOS player N" and carrying a made-up address, so that the kernel's own PlayStation driver makes its gamepad, motion and touchpad devices with one uniq and the emulator's SDL pairs the player's tilt to the pad by itself. The console tells its stand-ins from real pads by that name, not by their id. The plain uinput controller stays for the emulators that read no motion, and for a console where the stand-in cannot be made.
- **Date:** 2026-11-10
- **Why:** SDL reads a pad's motion only from a kernel sensor device whose uniq is the pad's own, and uinput cannot set one, so no motion could ever reach a plain virtual controller. The kernel's PlayStation driver is the one driver that makes such a pair for a device the console can create, and it takes only Sony's ids. Of those, the DualSense Edge is the one no pad in a living room is likely to share, which matters because the console can no longer ignore its own stand-ins by id and goes by their name instead. USB rather than Bluetooth: the USB report carries no checksum, and SDL's own database has a Bluetooth entry for the Edge laid out for the kernel's generic driver, which would scramble the buttons of a stand-in the PlayStation driver lays out.
- **Numbers:** #669, "Gyro for Switch, Wii U and Vita: a virtual pad that carries the player's tilt"; pull request #696, "Switch: a stand-in DualSense carries the player's tilt into Eden (#669, part one)".
- **Replaces:** none.
