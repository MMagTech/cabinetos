# Packages CabinetOS actually cares about in the Bazzite base, in AREAS, and
# what to check on the A9 when an area changes.
#
# Used by ci/check-base-update.sh (through ci/base-report.py) to decide whether
# a Bazzite update is RELEVANT (a human should look at it before merging) or
# ROUTINE (it is almost certainly fine and can be merged on the strength of a
# green build), and to write the pull request's update notes and its checks.
#
# Bazzite rebuilds daily. Most of those rebuilds move packages CabinetOS has no
# opinion about — desktop applications, fonts, translations, Windows
# compatibility. Without this filter, base bumps become a stream of noise and
# stop being read, which is worse than not having them at all.
#
# THE LINES (2026-10-09):
#
#   area: <name>      starts an area; the patterns below it belong to it. The
#                     name is what the update notes and the checks say, so it
#                     is written for a player, not for us.
#   <glob>            a package: one shell glob per line, matched against the
#                     package NAME only. A package's Terra build (terra-<name>)
#                     matches its name's pattern too: Terra's WirePlumber
#                     replaced Fedora's in 44.20260929, and the old list called
#                     that "WirePlumber removed" and never showed the new one.
#   log: <check> :: <command>
#                     a check the A9's log answers, once it runs the testing
#                     image. tools/base-checks.sh runs the command there in
#                     bash as `cabinet`, no sudo; exit 0 is a pass, and what
#                     it prints is shown on a fail.
#   tv: <check>       a check that needs MMagTech's eyes or hands.
#   changelog: <part> :: <regex>
#                     which kernel changelog lines (kernel.org's, and the OGC
#                     kernel's own patches) are about a part the console uses.
#                     Python regex, matched against each commit's subject.
#   changelog-skip: <regex>
#                     a changelog line that matched a part but is not news for
#                     this console: another chip in the same driver, or a
#                     clean-up that fixes nothing. Any one matching drops it.
#   kind: stripped    the area's packages are ones CabinetOS removes, so a new
#                     version of one is not news; only a name appearing or
#                     going is.
#
# Only the areas an update changed get checks, and a check several of them
# ask for is listed once (MMagTech, 2026-10-09: "each time we do a base
# update, I can't sit here and troubleshoot the whole OS"). So write the same
# check with the same words wherever it appears. Keep the tv: lines few: a
# kernel or Mesa change gets a short broad check, not the whole OS.
#
# ---------------------------------------------------------------------------
# ADD TO THIS FILE AS THE PROJECT GROWS.
# Phase 3 added the frontend's runtime libraries and fonts. Phase 5 added the
# cores' own, on the day the image started carrying them. A package CabinetOS
# relies on that is not listed here can break silently in a base bump that
# looked routine.
# ---------------------------------------------------------------------------

# --- Kernel and boot -------------------------------------------------------
# A kernel change can take out controller drivers or graphics. Always look.
#
# Its checks are the short broad ones: a kernel touches nearly everything,
# so boot, picture, sound, network, a Bluetooth pad and one heavy game.
area: Kernel and startup
log: The A9 booted the image's own kernel :: [ "$(uname -r)" = "$(rpm -q --qf '%{VERSION}-%{RELEASE}.%{ARCH}' kernel-core)" ]
log: No service failed to start :: out=$(systemctl --failed --no-legend --plain); [ -z "$out" ] || { echo "$out"; exit 1; }
log: No kernel error this boot that the boot before did not have :: e() { journalctl -b "$1" -k -p err -o cat | sed -E 's/[0-9]+/N/g' | sort -u; }; new=$(comm -13 <(e -1) <(e 0)); [ -z "$new" ] || { echo "$new"; exit 1; }
log: The console came up on the GPU, not software drawing :: journalctl -b -t cabinetos-session -o cat | grep -q 'gamescope (drm) is up'
log: Wi-Fi or the cable is connected :: nmcli -t -f TYPE,STATE dev | grep -qE '^(wifi|ethernet):connected'
log: Bluetooth is on :: bluetoothctl show | grep -q 'Powered: yes'
log: The sound devices are there :: wpctl status | sed -n '/^Audio/,/^Video/p' | grep -q '\[alsa\]'
tv: Picture: after the restart Home comes up on the TV, sharp
tv: Sound: Home's sounds play from the TV
tv: A Bluetooth pad: turn on a paired pad; it connects and moves around Home
tv: One heavy game: a PS2 or GameCube game plays smoothly for a minute, with sound
#
# Kernel fixes worth reading, by part (agreed 2026-10-09). The parts are the
# drivers the A9 loads (lspci -k, lsmod): its Wi-Fi is an MT7925, not the
# MT7921 the first notes said, and its Bluetooth is that card's (btmtk over
# btusb). Other machines' parts are not listed: the notes say what was fixed
# for the hardware this console is tested on, and other machines report.
changelog: Radeon graphics :: ^(drm/)?amd(gpu)?([/:])
changelog: Display over HDMI :: ^drm/(edid|display)\b|^drm: (?![\w-]+: )
changelog: Wi-Fi :: ^wifi: (mt76: (mt7925|mt792x|connac|mt76_connac)\b|mt76: (?!mt7\d{2,3}[a-z]?\b)|mac80211:|cfg80211:)
changelog: Wired network :: ^(net: )?r8169:
changelog: Bluetooth :: ^Bluetooth: (?!(btintel|btrtl|btbcm|btqca|hci_qca|btnxpuart|hci_bcm|hci_bcm4377|btmrvl|hci_h5|hci_ll|hci_intel|btsdio|hci_vhci|virtio_bt|btmtksdio|btmtkuart|hci_uart|hci_ldisc)\b)
changelog: Controllers :: ^HID: ((core|input|hidraw|uhid|usbhid|generic|playstation|sony|nintendo|microsoft|steam|wiimote|8bitdo|google)\b|hid-(core|input|playstation|sony|nintendo|microsoft|steam|wiimote|generic)\b|(?![\w-]+: ))|^Input: (xpad|joydev|uinput|evdev|ff-core|ff-memless)\b
changelog: Sound :: ^ALSA: (hda|pcm|core|control|timer)\b
changelog: USB :: ^(usb|USB): (xhci|core|hub)\b|^xhci\b|^usb: storage: uas\b|^thunderbolt:
changelog: Sleep and power :: ^(platform/x86(/amd|: amd)|cpufreq: amd-pstate|cpufreq/amd-pstate)
# Radeon: GPU families and blocks that are not the 890M's (gfx11.5, display
# DCN 3.5, SMU 14). Its own may be named; another one named is not news.
changelog-skip: ^(drm/)?amd.*\b(gfx([6-9]|10|12)|gfx_v([6-9]|10|12)|vega\d*|smu ?(7|11|13)|SMU ?(7|11|13)|powerplay|dce\d*|DCE|si|cik|uvd|vce|xgmi|XGMI|dGPUs?|MST|multi-XCC|MI\d{3}|dcn(?!3[56])\d+)\b
# Wi-Fi: mt76's other chips and its router-only paths (WED, RRO), and the
# USB and SDIO cards; the A9's is an MT7925 on PCIe.
changelog-skip: ^wifi: mt76: .*\b(WED|RRO|SDIO|USB|mt76x\d+|mt7915|mt7996|MT7991A?|mt7615|mt7603|mt7921u)\b|^wifi: mt76: mt76x\d
# Bluetooth: other vendors' parts of btusb, and other MediaTek chips (one that
# names the MT7925 as well stays).
changelog-skip: ^Bluetooth: (btintel\w*|btqcomsmd|hci_mrvl|btmtksdio)\b|^Bluetooth: btusb: .*(\bQCA|\bIntel|\bRealtek|\bBroadcom|wcn\d+)|^(?!.*MT7925)Bluetooth: btmtk: .*\bMT79(20|21|22|61)\b
# Sound, USB, power: other machines' parts.
changelog-skip: ^ALSA: hda/.*\b(cix|ipbloq|tegra|intel|cs35l\d+|tas\d+)\b|^ALSA: hda: (cix|tegra)\b|^usb: storage: (?!uas)|hsmp|amd-pstate-ut
# A laptop's own quirk is not this console's; one naming GEEKOM would be.
changelog-skip: ^(?!.*GEEKOM).*\b([Qq]uirks? for|[Ff]ixup for|[Aa]dd (a )?quirk|[Aa]dd (new )?(VID|PID|ID)s?)\b
# Clean-ups and build fixes: nothing changes on a running console.
changelog-skip: \b([Rr]emove unused|unused-but-set|duplicate .*include|[Ss]ilence|[Ww]arnings?|32-?bit compile|[Aa]void build|[Cc]lean ?up|[Rr]ename some|kernel-doc|[Tt]ypo|annotations)\b|use guard\(\)

# --- Graphics --------------------------------------------------------------
# Phase 2 runs the frontend inside gamescope and Phase 5 runs emulators inside
# it. A gamescope or Mesa regression is a project-stopping event.
#
# `vulkan-*` and `mesa-*` became load-bearing for the PRODUCT on 2026-09-20,
# not just for gamescope: PlayStation 2 and GameCube render through Vulkan and
# the frontend dlopens libvulkan.so.1 itself. Losing the loader or the RADV
# driver takes those two systems out while every other core keeps working, so
# it is the quiet kind of breakage. build_files/build.sh asserts both, because
# a dlopen is invisible to `ldd` and therefore to require-frontend-libs.sh.
#
# Mesa also encodes Remote Play's stream (VA-API), and draws Steam's games.
area: Graphics

# --- The CORES' runtime, added 2026-09-19 ----------------------------------
# The image carries twenty-two emulator cores from that day. Their library
# dependencies had never been written down anywhere, and three of the
# frontend's own — named in build_files/require-frontend-libs.sh with a reason
# each — were not on this list either, which is precisely the gap the header
# above warns about.
#
# What makes them urgent rather than tidy: build_files/install-frontend.sh now
# runs `ldd` over the binary and all twenty-two cores and FAILS THE BUILD if
# anything is unresolved. So a base bump that drops one of these no longer
# ships a broken console — it produces a red image build with no obvious
# cause. Listing them here is what turns that into a base-bump pull request
# that says "read this" before anybody wastes an afternoon on it.
#
