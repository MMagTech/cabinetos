# Packages CabinetOS actually cares about in the Bazzite base.
#
# Used by ci/check-base-update.sh to decide whether a Bazzite update is
# RELEVANT (a human should look at it before merging) or ROUTINE (it is almost
# certainly fine and can be merged on the strength of a green build).
#
# Bazzite rebuilds daily. Most of those rebuilds move packages CabinetOS has no
# opinion about — desktop applications, fonts, translations, Windows
# compatibility. Without this filter, base bumps become a stream of noise and
# stop being read, which is worse than not having them at all.
#
# One shell glob per line. Matched against the package NAME only.
#
# ---------------------------------------------------------------------------
# ADD TO THIS FILE AS THE PROJECT GROWS.
# Phase 3 added the frontend's runtime libraries and fonts. Phase 5 added the
# cores' own, on the day the image started carrying them. A package CabinetOS
# relies on that is not listed here can break silently in a base bump that
# looked routine.
# ---------------------------------------------------------------------------

# --- Kernel and boot -------------------------------------------------------
# A kernel change can take out controller drivers or graphics. Always look.

kernel-*

rpm-ostree

systemd
systemd-*

plymouth*

# --- Firmware --------------------------------------------------------------
# ADDED 2026-09-17, because the first real base bump this tool ever classified
# got this wrong. It reported "1 change to packages CabinetOS depends on" — a
# Fanatec steering wheel driver — while amd-gpu-firmware, amd-ucode-firmware
# and linux-firmware itself went BACKWARDS by a month, 20260910 to 20260810,
# and were filed under the full diff as though they were translations.
#
# The reference hardware is a GEEKOM A9 Pro: AMD, with Radeon 890M integrated
# graphics
# doing all of the rendering and all of the emulation. Its GPU firmware and its
# CPU microcode are not incidental to this project, they are the machine. A
# firmware package moving in either direction — and backwards especially — is a
# "read this" event.
#
# Kernel modules were already watched through kmod-*; firmware is a different
# kind of thing and matched none of the patterns here.
linux-firmware
linux-firmware-*
amd-gpu-firmware
amd-ucode-firmware
intel-gpu-firmware
intel-audio-firmware
nvidia-gpu-firmware
*-firmware

# --- The frontend's own runtime ---------------------------------------------
# Phase 3 links against these and the OS image is the only place they come
# from: there is no bundling and no vendoring, deliberately, so a security fix
# in the base is a security fix in the frontend. Every one of them was already
# present in Bazzite, which is why the frontend adds nothing to the image — and
# exactly why a base bump that drops one would be silent and fatal.
SDL3
SDL3-*
freetype
freetype-*
libjpeg-turbo
libpng
libwebp
# The type ramp. The design system names Noto Sans, and Noto Sans CJK is not
# optional: a ROM library is full of Japanese titles and Noto Sans has no
# coverage for them, so losing the CJK package turns every one of them into a
# row of boxes.
google-noto-sans-fonts
google-noto-sans-cjk-fonts
google-noto-fonts-common

# --- The CORES' runtime, added 2026-09-19 ----------------------------------
# The image carries twenty-one emulator cores from that day. Their library
# dependencies had never been written down anywhere, and three of the
# frontend's own — named in build_files/require-frontend-libs.sh with a reason
# each — were not on this list either, which is precisely the gap the header
# above warns about.
#
# What makes them urgent rather than tidy: build_files/install-frontend.sh now
# runs `ldd` over the binary and all twenty-one cores and FAILS THE BUILD if
# anything is unresolved. So a base bump that drops one of these no longer
# ships a broken console — it produces a red image build with no obvious
# cause. Listing them here is what turns that into a base-bump pull request
# that says "read this" before anybody wastes an afternoon on it.
#
# Read off `ldd` against the real binaries rather than guessed at. libX11 and
# libXext are PPSSPP's, which nothing had noticed until the control run.
libcurl
libcurl-minimal
json-c
libarchive
zlib-ng-compat
libzip
libX11
libXext
libxkbcommon*
libudev*
